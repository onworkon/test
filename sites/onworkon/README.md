# onworkon

`ui0.txt` 기반 모바일 시작 화면입니다.

## 실행

Node.js 22에서 실행합니다.

```sh
npm ci
npm run dev
```

`http://localhost:5173`에서 확인합니다. 이름 저장 API를 사용하므로 HTML 파일을 직접 여는 대신 서버를 실행해야 합니다.

## 화면과 입력

시작 화면의 영문은 `1.png`와 원본 `ui0.txt`에 맞춘 PP Supply Mono, 한글은 Pretendard Regular를 사용합니다. 글자 크기는 14px, 자간 -4%(`-0.04em`, 14px에서 -0.56px), 중앙 정렬입니다. 단어 사이 공백과 질문·입력란 사이 간격은 기존보다 2pt(약 2.67px) 줄였습니다. 텍스트와 입력란은 시안보다 20px 위로 이동하여 현재 문장은 y353에 표시됩니다. 화면을 터치하면 현재 문장이 y320으로 이동하면서 불투명도가 20%로 줄고, 다음 문장이 y353에서 타이핑됩니다. 위 문장은 다음 터치에서 아래 문장이 올라올 때까지 유지됩니다.

- 첫 `Hello!` 화면은 터치할 때까지 유지됩니다.
- 타이핑 도중 터치하면 해당 문장만 완성되며, 다음 문장으로 넘어가지는 않습니다.
- 이름·코드 질문 뒤의 입력 밑줄도 같은 타이핑 속도로 네 단계에 걸쳐 나타납니다. 도중에 화면을 터치하면 문장과 밑줄이 함께 완성됩니다.
- 입력란과 밑줄의 너비는 실제 글꼴·자간·공백 간격으로 표시된 텍스트를 측정합니다. 한글 조합 중, 조합 완료, 웹폰트 로딩 완료 시에도 갱신하며, 한글·영문 혼합 입력과 삭제에 맞춰 늘어나거나 줄어듭니다.
- 이름·코드는 다음 단계로 넘어가기 전까지 수정할 수 있습니다. 밑줄 주변(높이 44px의 입력란과 좌우 12px 여유)을 터치하면 입력란에 초점이 맞춰집니다.
- 이름·코드 입력 후 바깥을 첫 번째 터치하면 키보드와 밑줄을 닫고 입력값을 유지합니다. 두 번째 바깥 터치에서 이름 저장 또는 코드 검증 후 다음 단계로 진행합니다. Enter도 같은 두 단계로 동작하며 빈 값으로는 진행하지 않습니다.
- 첫 번째 터치 후에도 입력란 주변을 다시 터치하거나 키보드로 초점을 옮기면 밑줄이 돌아오며 수정할 수 있습니다. 수정에 들어가면 확인 상태가 초기화되어 바깥을 다시 두 번 터치해야 진행합니다.
- 입력 가능 여부는 밑줄로만 표시합니다. 저장 중에는 잠시 입력을 잠그며, 실패하면 다시 수정하거나 바깥 터치로 재시도할 수 있습니다. 같은 이름의 재시도는 같은 제출 ID를 사용하고, 수정한 이름은 새 ID로 제출합니다.
- 이름·코드 입력 글자는 질문과 기준선을 맞추고, 밑줄은 입력란 상단에서 30px 위치에 표시합니다.
- 다음 터치마다 `Were you invited?`, `Please provide the code. :` 순서로 진행합니다.
- 초대 코드는 `card` → `/card.html`, `work` → `/work.html`, `client` → `/workspace.html`로 연결됩니다. 영문 키보드를 사용하고 앞뒤 공백 및 대소문자는 구분하지 않습니다. 위의 두 단계 확인 후 이동하며, 기존 `0000`과 등록되지 않은 코드는 거절합니다.
- 모든 페이지 하단 중앙에는 `: 페이지명` 형태의 공통 입력란이 있습니다. 페이지명을 눌러 코드를 입력하고 Enter 또는 모바일 키보드의 이동 키로 이동합니다. 코드는 `home`, `card`, `work`, `client`, `about`, `portfolio`, `contact`이며, 앞뒤 공백과 대소문자는 구분하지 않습니다. `home`은 시작 화면, `client`는 기존 세 메뉴 랜딩 화면입니다.
- 공통 이동란에는 현재 페이지 코드를 표시하고 편집 중에만 밑줄을 보여줍니다. 등록되지 않은 코드는 오류를 표시하며 페이지를 유지하고, Escape 또는 다른 곳을 누르면 현재 코드로 돌아옵니다. 같은 페이지 코드는 새로고침하지 않습니다. 시작 화면의 이름 입력과 두 번 터치 동작은 이동란 편집에 영향을 받지 않습니다.
- 기존 Back·Reset 버튼은 제거했습니다. `card`는 앞·뒷면 명함 이미지를 입힌 3D 카드입니다. 상하좌우·대각선 드래그로 제한 없이 회전하며, 손을 놓으면 짧은 관성이 남습니다. 화살표 키로도 회전하고 R 키로 처음 각도로 돌아옵니다. 모션 줄이기 설정에서는 관성을 생략합니다.
- 카드 배경 박스는 캔버스의 상단·좌우 안쪽 32px, 하단 안쪽 52px에 표시하며, 4px 둥근 모서리와 불투명도 5%의 검정 배경을 적용합니다. `Drag to rotate` 문구의 상단은 박스 하단에서 16px 아래에 맞추며, 글자 크기는 기본 14px에서 2pt를 줄인 약 11.33px입니다. 배경 박스는 카드 표시·조작 영역을 제한하지 않으며, 카드와 그림자·대체 이미지는 전체 캔버스 영역에서 표시됩니다. 포커스 테두리는 배경과 같은 레이어에 그려 카드 그래픽 아래에 표시합니다.
- 카드 본체는 불투명도 96%, 85mm 폭 기준 약 1.3mm 두께의 둥근 모서리와 반사 재질로 구성했습니다. 반대편 인쇄는 판을 통해 약하게 비칩니다. WebGL을 사용할 수 없으면 앞·뒷면 정지 이미지를 보여줍니다.
- 3D 스크립트와 이미지가 로딩되는 동안에는 대체 이미지를 숨기고 첫 3D 프레임이 그려진 후 카드를 표시합니다. 스크립트 로딩·3D 초기화 실패 또는 WebGL 연결이 끊긴 경우에만 정지 이미지를 표시하며, JavaScript를 끈 환경에서도 이미지를 볼 수 있습니다.
- `work` 페이지는 현재 로고와 서체를 유지한 제목 및 공통 코드 이동란을 준비했습니다. 실제 내용은 HTML에 추가할 수 있습니다.
- `client` 코드는 기존 `/workspace.html` 랜딩 화면으로 연결되며 `→ About on`, `→ portfolio`, `→ contact` 세 텍스트 링크가 있습니다. 각 상세 경로(`/about.html`, `/portfolio.html`, `/contact.html`)는 제목과 공통 코드 이동란을 준비했으며 실제 내용은 추후 추가합니다.
- 랜딩 메뉴 세 줄은 12pt, 줄 높이 40px, 자간 0, 좌측 정렬이며 묶음의 시작 위치는 모바일 화면 기준 x48px, y290px입니다. 단어 사이 공백은 기존 -2pt 설정을 유지합니다.
- 랜딩 메뉴는 마우스를 올리거나 키보드로 초점을 옮기면 Regular 폰트에 0.25px 윤곽선을 적용해 살짝 두껍게 표시합니다.
- 현재 초대 코드는 화면 전환을 위한 클라이언트 검증이며, 각 페이지 자체의 접근 권한을 제한하지 않습니다.
- 키보드에서는 화면 영역에 초점을 둔 뒤 Enter 또는 Space로 진행할 수 있습니다. 모션 줄이기 설정에서는 타이핑과 이동 애니메이션을 생략합니다.

상·하단 기기 표시 영역은 시각화용 장식이므로 실제 페이지에서 제거했습니다. 로고는 제공된 `logo.svg`를 54×40px로 왼쪽 32px, 위쪽 36px에 배치했습니다. 이름과 코드 입력란은 질문 옆에 한 줄로 표시합니다. 큰 화면에서도 최대 폭 480px의 모바일 화면으로 표시됩니다.

Pretendard는 [공식 v1.3.9 배포본](https://github.com/orioncactus/pretendard/tree/v1.3.9)의 Regular WOFF2를 `dist/assets/`에 포함했습니다. 한글 및 한글 자모 범위에만 적용하며 영문·숫자는 PP Supply Mono를 사용합니다. SIL Open Font License 원문은 `dist/assets/Pretendard-LICENSE.txt`에 함께 배포합니다.

명함 원본은 제공된 투명 배경 `f.png`와 `b.png`를 그대로 복사한 `dist/assets/card-front.png`, `dist/assets/card-back.png`입니다. 같은 크기·비율의 투명 배경 이미지를 교체하면 아트워크를 수정할 수 있습니다. 현재 비율은 976 × 590이며, 변경 시 `src/card-viewer.js`의 카드 비율도 맞춥니다. 일러스트레이터에서 SVG로 내보내는 경우 텍스트를 윤곽선으로 변환하고 이미지 경로를 변경합니다.

3D 코드는 `src/card-viewer.js`, 전용 스타일은 `dist/card.css`에 있습니다. `npm run build`와 `npm run dev` 시작 시 Three.js를 포함한 `dist/card-viewer.js`를 생성합니다. 드래그·관성이 멈추면 렌더링도 멈추며 픽셀 비율은 2로 제한합니다. Three.js의 MIT 라이선스는 `dist/assets/three-LICENSE.txt`에 포함했습니다.

## 이름 DB

- 로컬 위치: `data/visitor-names.sqlite` (SQLite)
- Vercel: 연결된 Neon PostgreSQL (`DATABASE_URL` 환경 변수 사용)
- 테이블: `visitor_names`
- 컬럼: `id`(입력 건 식별자), `name`(이름), `created_at`(UTC 저장 시각)
- 저장 API: `POST /api/names`
- 새로고침 또는 서버 재시작 후에도 기록이 유지됩니다.
- 같은 이름을 입력한 별도 방문은 각각 저장하고, 동일 입력의 중복 터치나 재시도는 한 건으로 처리합니다.
- 이름 목록과 DB 파일은 웹에서 제공하지 않습니다. DB 파일은 Git에서도 제외합니다.
- 다른 저장 위치가 필요하면 `NAMES_DB_PATH` 환경 변수를 지정합니다.

로컬 서버는 SQLite를 사용하고, Vercel의 `/api/names`는 Neon PostgreSQL을 사용합니다. 기존 로컬 기록은 SQLite에 유지되며 배포된 사이트에서 새로 입력하는 이름은 Neon에 저장합니다. 로컬 DB·환경 변수 파일·시안 원본은 `.vercelignore`에서 업로드 제외했습니다.

## Vercel 배포

`vercel.json`은 `dist` 정적 화면과 `api/names.js`를 함께 배포합니다. Vercel 빌드에서는 이름 DB 연결을 확인하고 `db/migrations/001_visitor_names.sql`로 테이블을 준비합니다. DB 설정이 없으면 배포 빌드가 실패하도록 했습니다.

```sh
vercel deploy --prod
```

Neon 연결 시 제공되는 `DATABASE_URL`은 서버 환경 변수로만 사용합니다. `.env.local`을 사용해 DB만 초기화할 때는 다음 명령을 실행할 수 있습니다.

```sh
node --env-file=.env.local scripts/migrate-postgres.mjs
```

`.openai/hosting.json`은 이전 Sites 등록 정보이며 Vercel 배포에는 사용하지 않습니다.
